# Deployment Guide

Target stack (free tier to start):

| Piece | Service | Region |
| --- | --- | --- |
| Storefront | Vercel Hobby | closest to users |
| Backend (Medusa) | Render Free | Singapore |
| PostgreSQL | Supabase Free | Mumbai (ap-south-1) |
| Redis (recommended) | Upstash Free / Redis Cloud Free | Singapore |
| Order mirror (optional) | Google Sheets + Apps Script | - |

Free-tier caveats: Render sleeps after 15 minutes idle (about a minute to wake), Supabase pauses a project after 7 days of low activity, and Render's 512 MB free instance can fail the Medusa build. If that happens, upgrade Render to Starter ($7/mo) or move the backend to Railway Hobby ($5/mo) with the same commands.

## 0. Secrets rule

- Only `apps/backend/.env.template` and `apps/storefront/.env.template` are committed.
- Real values live in local `.env` files and in the Render/Vercel dashboards.
- `.gitignore` already excludes `.env`, `.env.local`, `.pgdata/`, `.next/`, `.medusa/`, logs and `.vercel`.
- Before pushing, run `git status --short` and confirm no env file or `.pgdata` folder is staged.
- If a secret ever lands in Git, rotate it (regenerate and update the host). Removing the commit is not enough.

## 1. Push to GitHub

```powershell
cd C:\Users\gaura\jsb-sons
git init
git add .
git status
git commit -m "JSB Sons storefront and Medusa backend"
git branch -M main
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

`render.yaml` at the repo root is picked up automatically by Render later.

## 2. Create the production database (Supabase)

1. Create a project, region **Mumbai (ap-south-1)**, save the database password.
2. Go to Connect and copy the **Session pooler** connection string (port `5432`).
   Do not use the transaction pooler (`6543`) and do not rely on the direct host on
   the free plan (IPv6 only).
3. Ensure it ends with `?sslmode=require`. It looks like:

```text
postgresql://postgres.<project-ref>:<password>@aws-0-ap-south-1.pooler.supabase.com:5432/postgres?sslmode=require
```

This value becomes `DATABASE_URL`. It is read in `apps/backend/medusa-config.ts`
(`projectConfig.databaseUrl`).

## 3. Load schema and data into the cloud database (from your laptop)

Medusa migrations are not run automatically on deploy. Run them once from the repo:

```powershell
cd C:\Users\gaura\jsb-sons\apps\backend
$env:DATABASE_URL = "postgresql://...:5432/postgres?sslmode=require"

npx medusa db:migrate
npx medusa user -e admin@jsbsons.local -p "<strong-admin-password>"
npm run seed

Remove-Item Env:DATABASE_URL
```

Notes:

- The `$env:DATABASE_URL` override wins over `.env` for this terminal only; your local database is untouched.
- `npm run seed` wipes and rebuilds catalog data in the target database. Never point it at a database holding real orders.
- The seed prints the publishable API key. You can also read it in Supabase SQL editor:

```sql
select token from api_key where type = 'publishable' and deleted_at is null;
```

## 4. Deploy the backend (Render)

1. Render dashboard -> New -> **Blueprint** -> connect the GitHub repo. Render reads `render.yaml`.
2. When prompted, enter `DATABASE_URL` (the Supabase session pooler string from step 2).
   The CORS values default to localhost; you will update them in step 6. Redis can be
   added later from the Render dashboard (Environment -> Add Environment Variable).
3. `JWT_SECRET`, `COOKIE_SECRET`, `AUTH_MFA_ENCRYPTION_KEY` are generated by the blueprint.
4. Deploy and confirm `https://<service>.onrender.com/health` returns `OK`.

Manual service setup (if you skip the blueprint):

```text
Runtime: Node
Build:  npm ci --include=dev && npm run build --workspace=@dtc/backend
Start:  npm run start --workspace=@dtc/backend
Health: /health
```

`PORT` is provided by Render and honored by the Medusa CLI. Do not hardcode 9000.

Environment variables used by the backend:

| Variable | Read in | Notes |
| --- | --- | --- |
| `DATABASE_URL` | `apps/backend/medusa-config.ts` | Must be reachable from Render (pooler, IPv4) |
| `REDIS_URL` | `apps/backend/medusa-config.ts` | Optional locally, recommended in production; use `rediss://` for TLS |
| `JWT_SECRET` | `apps/backend/medusa-config.ts` | Required in production (server refuses to boot without it) |
| `COOKIE_SECRET` | `apps/backend/medusa-config.ts` | Required in production |
| `AUTH_MFA_ENCRYPTION_KEY` | Medusa auth module | Optional unless MFA is enabled |
| `STORE_CORS` | `apps/backend/medusa-config.ts` | Storefront origin(s), comma separated |
| `ADMIN_CORS` | `apps/backend/medusa-config.ts` | Backend's own admin URL + Studio origin |
| `AUTH_CORS` | `apps/backend/medusa-config.ts` | Same as admin plus storefront |
| `GOOGLE_SHEETS_WEBHOOK_URL` | `apps/backend/src/lib/sheets.ts` | Step 7, optional |
| `GOOGLE_SHEETS_TOKEN` | `apps/backend/src/lib/sheets.ts` | Step 7, optional |
| `NODE_ENV` | Medusa runtime | Set to `production` |

Without `REDIS_URL`, Medusa logs "Local Event Bus installed" and keeps queues in
memory. That works for a single instance but loses in-flight jobs on restart.

## 5. Deploy the storefront (Vercel)

1. Vercel -> Add New -> Project -> import the GitHub repo.
2. Set **Root Directory** to `apps/storefront`. Framework preset: Next.js. Node 22.
3. Add Environment Variables (Production and Preview):

| Variable | Value | Read in |
| --- | --- | --- |
| `NEXT_PUBLIC_MEDUSA_BACKEND_URL` | `https://<service>.onrender.com` (no trailing slash) | `lib/api.ts`, `lib/client-api.ts`, `lib/admin-api.ts`, `next.config.mjs` |
| `NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY` | publishable key from step 3 | `lib/api.ts`, `lib/client-api.ts` |
| `NEXT_PUBLIC_SITE_URL` | `https://<project>.vercel.app` | `lib/cookies.ts` (Secure cookie flag), `app/layout.tsx` |
| `JSB_ADMIN_MOBILE` | the 10-digit mobile you use to sign into Studio | `lib/admin-api.ts` |
| `JSB_ADMIN_EMAIL` | `admin@jsbsons.local` (must match the Medusa admin user) | `lib/admin-api.ts` |

4. Deploy, then copy the production domain.
5. Optional: Project Settings -> Functions -> Region -> Singapore (`sin1`) so server-side
   fetches stay close to the backend.
6. `NEXT_PUBLIC_*` values are baked at build time. Changing them requires a redeploy.

## 6. Finish CORS (required for cart and checkout)

Set these on the Render backend, replacing the placeholder domain with the Vercel domain:

```text
STORE_CORS=https://<project>.vercel.app,http://localhost:3000
ADMIN_CORS=https://<project>.vercel.app,https://<service>.onrender.com,http://localhost:9000
AUTH_CORS=https://<project>.vercel.app,https://<service>.onrender.com,http://localhost:9000
```

Save and redeploy the backend. Browser-side cart calls fail without this. Medusa does
not support `*.vercel.app` wildcards, so preview deployments each need their own origin
or should use the production domain.

## 7. Google Sheets order mirror (optional)

1. Create a Google Sheet. Open Extensions -> Apps Script and paste
   `apps/backend/scripts/google-sheet-webhook.gs`.
2. Replace `TOKEN` with a long random string.
3. Deploy -> New deployment -> Web app. Execute as **Me**, access **Anyone**.
4. Copy the `/exec` URL and generate a matching token value.
5. Add both to Render:

```text
GOOGLE_SHEETS_WEBHOOK_URL=https://script.google.com/macros/s/.../exec
GOOGLE_SHEETS_TOKEN=<same string as TOKEN>
```

6. Backfill existing orders from your laptop (with the cloud `DATABASE_URL` set):

```powershell
cd C:\Users\gaura\jsb-sons\apps\backend
$env:DATABASE_URL = "postgresql://...:5432/postgres?sslmode=require"
npm run sync:sheets
Remove-Item Env:DATABASE_URL
```

Rows are upserted by internal order ID, so re-running is safe. New orders and Studio
status changes sync automatically. If the webhook is down, checkouts still complete.

If the Apps Script was created standalone (not from the sheet), add a Script Property
`SPREADSHEET_ID` with the sheet ID.

## 8. Verify the deployment

- `GET https://<service>.onrender.com/health` returns `OK`.
- Storefront home shows products and images.
- `/admin/login` accepts the mobile in `JSB_ADMIN_MOBILE` with the admin password.
- Add to cart -> checkout -> place a small pay-on-delivery test order.
- The order appears in `/account` for the signed-in customer and in `/admin/orders`.
- Change the status in the order detail page; the customer sees it and the Sheets row updates.
- Upload a new product image in the built-in admin, then confirm it renders on the storefront (the image host is derived from `NEXT_PUBLIC_MEDUSA_BACKEND_URL`).

## 9. Not connected yet

Payments

- Checkout uses `pp_system_default` (pay on delivery). There is no gateway.
- To add Razorpay: create a Medusa payment provider (module under
  `apps/backend/src/modules/`), register it in `apps/backend/medusa-config.ts`, enable it
  for the INR region, add the key env vars on Render, and add the redirect/verification
  flow in `apps/storefront/app/(store)/checkout/page.tsx` plus a webhook route under
  `apps/backend/src/api/`. Razorpay's India pricing has no monthly fee.

Email / SMS

- New orders only create Studio notifications (`apps/backend/src/subscribers/order-placed.ts`)
  and a Sheets row. Add a provider (e.g. Resend) in that subscriber or as a Medusa
  notification provider; store the API key in the backend environment.

Backups

- Supabase Free has no automatic backups. Move to Pro before taking real orders, or run a
  scheduled `pg_dump` from a machine that can reach the database.

Media

- Product images live in `apps/storefront/public/products` and are normalized by
  `imagePath` in `apps/storefront/lib/format.ts`. Images uploaded through the Medusa admin
  are served by the backend and allowed through the env-driven `remotePatterns` in
  `apps/storefront/next.config.mjs`.

## 10. Operations

- Rotate secrets by generating new values (`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`)
  and updating Render. Rotating `JWT_SECRET` signs out customers and admin sessions.
- Keep `render.yaml` and the env templates in sync with any new variable.
- Supabase Free pauses after 7 days of inactivity; the first request after a pause may be slow.
- Custom domain: add it in Vercel, set `NEXT_PUBLIC_SITE_URL` and the CORS values to that
  domain, redeploy both apps.
